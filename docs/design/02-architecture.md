## Window State Machine

### States

```
          ┌──────────┐
          │  HIDDEN  │  Window.Hide(); WebView2 pauses navigation
          └────┬─────┘
     ToggleHide │  ▲ ToggleHide
               ▼  │
          ┌──────────┐
  ┌──────▶│  LOCKED  │◀──────┐  WS_EX_TOPMOST | WS_EX_TRANSPARENT
  │       └────┬─────┘       │  WebView2 renders; mouse passes through
  │  ToggleLock│  ▲ ToggleLock │  Topmost timer: SetWindowPos every 2s
  │            ▼  │            │
  │       ┌──────────┐        │
  └───────│   EDIT   │────────┘
          └──────────┘   WS_EX_TOPMOST only; WS_EX_TRANSPARENT OFF
          Mouse normal; EditOverlay visible; WebView2 interactable
```

### Transition Table

```
┌──────────┬──────────┬────────────────────┬──────────────────────┐
│ From     │ To       │ Trigger            │ Actions              │
├──────────┼──────────┼────────────────────┼──────────────────────┤
│ Hidden   │ Locked   │ ToggleHide hotkey  │ Show(), start timer  │
│ Locked   │ Hidden   │ ToggleHide hotkey  │ Hide(), stop timer   │
│ Locked   │ Edit     │ ToggleLock hotkey  │ Remove TRANSPARENT,   │
│          │          │                    │ show EditOverlay,     │
│          │          │                    │ stop timer            │
│ Edit     │ Locked   │ ToggleLock hotkey  │ Add TRANSPARENT,      │
│          │          │                    │ hide EditOverlay,     │
│          │          │                    │ start timer           │
└──────────┴──────────┴────────────────────┴──────────────────────┘

Illegal transitions (enforced by guard):
  Hidden → Edit        (must go through Locked first)
  Any    → Any (same)  (idempotent toggle — no-op, no exception)
```

### WS_EX Style Lifecycle

```
Startup ─────────────────────────────────────────────▶ Initial: Locked
  │  WS_EX_TOPMOST | WS_EX_TRANSPARENT
  │  Topmost timer started

ToggleLock (Locked → Edit):
  │  SetWindowLong: remove WS_EX_TRANSPARENT
  │  SetWindowPos: HWND_TOPMOST, SWP_NOACTIVATE
  │  Kill topmost timer
  │  Show EditOverlay (position/size/opacity/zoom sliders + lock button)

ToggleLock (Edit → Locked):
  │  Hide EditOverlay
  │  SetWindowLong: add WS_EX_TRANSPARENT
  │  SetWindowPos: HWND_TOPMOST, SWP_NOACTIVATE
  │  Start topmost timer (2s interval)

Shutdown ─────────────────────────────────────────────▶
  │  Kill topmost timer
  │  Save settings (atomic write)
  │  UnregisterHotKey for all registered keys
  │  WebView2: CoreWebView2.Close() → Environment.Dispose()
  │  Mutex.ReleaseMutex()
```

### Navigation Whitelist

```csharp
// WebView2Setup.cs — NavigationStarting handler
void OnNavigationStarting(object sender, CoreWebView2NavigationStartingEventArgs e)
{
    var uri = new Uri(e.Uri);
    if (uri.Host != "helltides.com" && !uri.Host.EndsWith(".helltides.com"))
    {
        e.Cancel = true;
        return;  // block all non-helltides domains
    }
    // Allow: https://helltides.com/* and subdomains
}

// NewWindowRequested handler — block all popups
void OnNewWindowRequested(object sender, CoreWebView2NewWindowRequestedEventArgs e)
{
    e.Handled = true;  // suppress all popups/new windows
}

// DownloadStarting handler — block all downloads
void OnDownloadStarting(object sender, CoreWebView2DownloadStartingEventArgs e)
{
    e.Cancel = true;  // block all downloads
}

// NavigationCompleted handler — distinguish errors from "no active events"
void OnNavigationCompleted(object sender, CoreWebView2NavigationCompletedEventArgs e)
{
    if (!e.IsSuccess)
    {
        // HTTP error or network failure → trigger retry + error banner
        RetryOrShowError(e.WebErrorStatus);
    }
    // else: success — may or may not show active events (normal)
}
```

## Hotkey Registration & Lifecycle

### Registration Flow

```
App.OnStartup() → MainWindow.SourceInitialized
  │
  ├─ Load HotkeyBindings from settings.json
  │   └─ Default: Ctrl+Shift+M/H/Plus/Minus/Up/Down/R/F5
  │
  ├─ For each binding:
  │   └─ win32.RegisterHotKey(hwnd, id, modifiers, key)
  │       │
  │       ├─ TRUE  → record as active; log DEBUG "Hotkey N registered"
  │       └─ FALSE → log WARN "Hotkey N registration conflict (0x{key:X})"
  │                   → continue; hotkey unavailable but app runs
  │
  └─ WndProc catches WM_HOTKEY (id 0x0000–0xFFFF range)
      └─ HotkeyDispatcher.Dispatch(id) → fires command
```

### Conflict Handling

`RegisterHotKey` returns `false` when another app already owns the combination. Strategy:
1. Log the conflict with the hotkey ID and key code.
2. Continue startup without that hotkey.
3. User can change bindings via `%LocalAppData%\Anhei4Map\settings.json`.
4. No runtime UI for rebinding — MVP defers the settings editor.
5. On settings file change (manual edit), restart picks up new bindings.

### Unregister at Shutdown

```
App.OnExit()
  └─ For each successfully registered hotkey:
      └─ win32.UnregisterHotKey(hwnd, id)
```

## Single Instance via Mutex

```csharp
// App.xaml.cs
static Mutex? _mutex;

protected override void OnStartup(StartupEventArgs e)
{
    _mutex = new Mutex(true, @"Global\Anhei4Map_SingleInstance",
                        out bool createdNew);
    if (!createdNew)
    {
        // Another instance already running
        _mutex.Dispose();
        _mutex = null;
        Shutdown();
        return;
    }
    // Continue startup...
}

protected override void OnExit(ExitEventArgs e)
{
    _mutex?.ReleaseMutex();
    _mutex?.Dispose();
}
```

## Window Bounds Recovery Algorithm

```
On startup, after loading saved placement:

1. Enumerate monitors via IWin32Interop.GetMonitorWorkingAreas()
2. rect = new Rect(saved.Left, saved.Top, saved.Width, saved.Height)
3. For each working area WA:
     intersection = Rect.Intersect(rect, WA)
     if intersection.Width * intersection.Height >= 0.2 * rect.Width * rect.Height:
       → OK, keep saved position
4. If no monitor has >= 20% overlap:
     → Reset to primary monitor: (WA.Right - 656, WA.Top + 16, 640, 360)
       (16px edge padding, 640x360 default size)
5. Clamp width/height: min 200x150, max = screen dimensions

On WM_DISPLAYCHANGE:
     Re-run steps 1-4 with CURRENT window position
```

## Retry Policy Algorithm

```
class RetryPolicy
{
    static readonly int[] Delays = { 0, 1000, 2000, 4000, 8000, 30000 };
    const int MaxRetries = 10;
    const int MaxDelayMs = 30000;

    // Returns wait time before next attempt, or null to stop
    int? NextDelay(int attemptNumber)
    {
        if (attemptNumber < 0) throw new ArgumentOutOfRangeException(...);
        if (attemptNumber >= MaxRetries) return null;
        if (attemptNumber < Delays.Length) return Delays[attemptNumber];
        return MaxDelayMs;
    }
}
```

Consumed by WPF on WebView2 navigation failure and mid-session navigation error.

## Exception & Shutdown Cleanup

```
App.DispatcherUnhandledException:  log FATAL + flush; show MessageBox; exit gracefully
TaskScheduler.UnobservedTaskException: log ERROR; don't crash
WebView2.CoreWebView2.ProcessFailed: log ERROR with ProcessFailedKind; if renderer,
                                       attempt restart navigation with retry policy
MainWindow.Closing:
  1. Unregister all hotkeys
  2. Save settings (atomic write)
  3. Stop topmost timer
  4. WebView2: CoreWebView2.Close(); environment?.Dispose()
  5. Mutex.ReleaseMutex()
  6. Log INFO Shutdown + flush
```
