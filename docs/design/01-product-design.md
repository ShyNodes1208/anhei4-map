## Problem Statement

Playing Diablo IV 在无边框窗口模式下，查看 https://helltides.com/ 的实时地图（绿色圈位置、事件倒计时）需要 Alt+Tab 切出游戏。每次切换打断游戏沉浸感，频繁操作导致体验很差。

目标：开发一个 Windows 桌面程序，把 Helltides.com 实时地图显示在桌面最上层，作为 Diablo IV 的无边框窗口覆盖层。用户只需扫一眼即可看到地图信息，不需要离开游戏。

## What Makes This Cool

- **零 Alt+Tab 游戏体验**——地图始终在屏幕角落可见，不打断战斗
- **鼠标穿透锁定模式**——锁定后鼠标点击穿透地图窗口直达游戏，不会误操作
- **全局快捷键全控制**——显示/隐藏、锁定/编辑、透明度、缩放全部键盘操作，手不离开游戏

## Constraints

### 固定技术栈（不可替换）

- C# / .NET 8 / WPF / Microsoft Edge WebView2
- xUnit 单元测试
- Win32 RegisterHotKey（全局快捷键）
- Win32 扩展窗口样式（WS_EX_TOPMOST、WS_EX_TRANSPARENT 鼠标穿透）
- JSON 本地设置持久化

### 安全红线（不可逾越）

- 不读取游戏进程、内存、文件和网络
- 不注入或 Hook 游戏
- 不模拟游戏键鼠
- 不自动寻路或定位玩家
- 不调用网站未公开 API
- 不爬取、下载或重新分发地图素材
- 不注入脚本隐藏广告或绕过限制

### 用户环境

- Windows 10/11，2560x1440 主分辨率
- Diablo IV 无边框窗口模式
- 单人本地使用
- 默认窗口约 640x360，位置在屏幕顶部或右上角

## Premises

以下前提已通过 Phase 3 挑战，记录为设计基线：

1. **WebView2 嵌入 Helltides.com 是最简路径**（未实测验证）——风险：网站改版可能影响渲染。缓解：退避重试 + 加载失败状态 UI + 运行中导航失败横幅。
2. **编辑/锁定/隐藏三状态足够**——风险：锁定模式下无法与网站交互。缓解：全局快捷键快速切换模式。
3. **全局快捷键可能与游戏冲突**（未实测验证）——风险：RegisterHotKey 注册失败。缓解：所有快捷键可通过 JSON 设置自定义、注册失败时记录日志并降级运行。
4. **WS_EX_TOPMOST 在 DirectX 12 无边框全屏下可能被压住**（未实测验证）——风险：小地图窗口不置顶。缓解：在锁定模式下每 2 秒通过 `SetWindowPos` 重新应用 `HWND_TOPMOST` + `SWP_NOACTIVATE`。如果仍不可靠，可能需要 `AttachThreadInput` 方案作为后备。
5. **JSON 文件单文件设置足够**——风险：写入时崩溃导致文件损坏。缓解：写入时使用原子写（写 `settings.json.tmp` + 重命名为 `settings.json`）。下次启动时如果发现残留 `.tmp` 文件，自动删除。如果 JSON 解析失败，回退默认值并备份损坏文件为 `settings.json.bak`。
6. **WS_EX_TRANSPARENT 可能与 WebView2 输入处理冲突**——风险：鼠标穿透的窗口扩展样式可能导致嵌入的 WebView2 控件无法接收鼠标事件。缓解：进入编辑模式时关闭 `WS_EX_TRANSPARENT`（只保留 `WS_EX_TOPMOST`），切换到锁定模式时重新开启。

## Approaches Considered

### Approach A: WPF 单体（最快出活）

所有逻辑——WebView2 宿主、热键注册、窗口拖动缩放、设置持久化——全部放在一个 WPF 项目的 code-behind 中。

- Effort: S（human: ~1 天 / CC: ~15 分钟）
- Risk: High——不可单元测试
- 优点：3-5 个文件即可跑出 MVP，Win32 互操作调用链短容易调试
- 缺点：code-behind 无法 xUnit 测试，窗口状态和设置耦合在一起最终变成 God class

### Approach B: 分层架构 + 可测试核心（已选）

WPF 只做 View 层。业务逻辑——热键命令调度、窗口状态机、设置序列化、窗口位置越界找回、退避重试——抽到独立 Core 类库。WPF 通过接口调用。xUnit 测试项目直接引用 Core，mock 掉 Win32 和 WebView2。

- Effort: M（human: ~3 天 / CC: ~45 分钟）
- Risk: Low——核心逻辑可全面测试
- 优点：约 8 条 MVP 涉及的状态逻辑可在 xUnit 中测试且不需要启动窗口，Win32/WPF 完全隔离在接口后
- 缺点：初期多建 2 个项目（Core + Tests），接口抽象需要纪律

### Approach C: 薄壳 + JS 注入（已排除——违反安全边界）

WPF 只做无边框窗口 + WebView2 + 热键转发。控制逻辑通过 `ExecuteScriptAsync` 注入 JS 到 Helltides.com 页面。

- 排除原因：违反安全红线"不注入脚本隐藏广告或绕过限制"。网站改版会 break JS 注入，且无法 xUnit 测试 JS 逻辑。

### 架构决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 项目分离 | WPF + Core + Tests 三个项目 | Core 无 UI 依赖，可直接 xUnit 测试 |
| Win32 隔离 | `IWin32Interop` 接口 | mock 掉 RegisterHotKey/WS_EX 等调用 |
| 状态管理 | 显式状态机（Edit/Locked/Hidden） | 三种状态转换可验证、可测试 |
| 设置持久化 | 原子写（temp file + rename） | 防止写入崩溃损坏 JSON |
| WebView2 初始化 | 异步 + 超时 + 退避重试 | 处理 Runtime 缺失和网络失败 |
| 单实例 | `Mutex` | 防止重复启动 |
| 日志 | 文本日志 `%LocalAppData%\Anhei4Map\app.log` | 调试热键冲突和窗口 Z-order 问题 |
| 关闭行为 | Alt+F4 完全退出（不最小化到托盘） | 简单可靠；下次启动恢复设置 |

### 窗口状态机

三种状态和合法转换：

```
           ┌──────────────┐
           │   Hidden     │  窗口不可见, WebView2 暂停导航
           └──────┬───────┘
          ToggleHide   ▲
           │          ToggleHide
           ▼           │
           ┌──────────────┐
    ┌─────▶│   Locked     │◀──────┐  鼠标穿透, WS_EX_TRANSPARENT 开启
    │      └──────┬───────┘       │  WebView2 继续渲染
    │      ToggleLock  │          │
    │             ▼    │  ToggleLock
    │      ┌──────────────┐       │
    └──────│    Edit      │───────┘
           └──────────────┘  鼠标正常, WS_EX_TRANSPARENT 关闭
                              显示编辑控制条, WebView2 可交互
```

| 状态 | 鼠标行为 | WS_EX_TRANSPARENT | WebView2 | 编辑控制条 |
|------|----------|-------------------|----------|-----------|
| Hidden | N/A（窗口隐藏） | N/A | 暂停导航（节省资源） | 不显示 |
| Locked | 穿透到游戏 | 开启 | 继续渲染 | 不显示 |
| Edit | 正常交互 | 关闭 | 可交互 | 显示（位置/大小/透明度/缩放控件） |

合法转换：Hidden ↔ Locked ↔ Edit。禁止 Hidden 直接转 Edit（必须先到 Locked）。

### WebView2 导航策略

`CoreWebView2.NavigationStarting` 事件中拦截所有非 helltides.com 的导航并取消。实现：

- 允许 `https://helltides.com/*` 及其子资源
- 阻止所有其他域（防止用户误操作离开地图页面）
- 阻止 `window.open` 弹出新窗口（`CoreWebView2.NewWindowRequested` 事件取消）
- 保留 `IsScriptEnabled = true`（网站正常功能需要 JavaScript）

### EditOverlay

`EditOverlay.xaml` 是 MainWindow 内嵌的覆盖面板（非独立窗口），在编辑模式下悬浮于 WebView2 上方。包含：位置拖动把手、窗口大小调整控件、不透明度滑块（10%–100%，10% = 几乎透明，100% = 完全不透明）、网页缩放控件（范围 25%–500%，步长 10%）、锁定按钮。退出编辑模式时自动隐藏。不透明度值在锁定模式下持续生效。

### 默认全局快捷键

| 组合键 | 命令 | 说明 |
|--------|------|------|
| Ctrl+Shift+M | ToggleLock | 编辑模式 ↔ 锁定模式 |
| Ctrl+Shift+H | ToggleHide | 显示/隐藏窗口 |
| Ctrl+Shift+Plus | ZoomIn | 网页放大 |
| Ctrl+Shift+Minus | ZoomOut | 网页缩小 |
| Ctrl+Shift+Up | OpacityUp | 不透明度增加（+10%，窗口更不透明） |
| Ctrl+Shift+Down | OpacityDown | 不透明度降低（-10%，窗口更透明） |
| Ctrl+Shift+R | ResetPosition | 恢复到默认位置和大小（640x360, 右上角） |
| Ctrl+Shift+F5 | Refresh | 刷新 WebView2 页面 |

所有快捷键通过 JSON 设置文件可自定义。注册失败时记录日志，应用程序继续运行——快捷键功能不可用但其他功能正常。

### 退避重试参数

WebView2 初始加载和运行中导航失败使用同一退避策略：

| 尝试 | 延迟 |
|------|------|
| 1（初始） | 立即 |
| 2 | 1 秒 |
| 3 | 2 秒 |
| 4 | 4 秒 |
| 5 | 8 秒 |
| 6+ | 30 秒（最大间隔） |

最多 10 次重试。所有重试失败后显示内嵌错误 UI："加载失败——Helltides.com 不可用。点击重试或按 Ctrl+Shift+F5。"运行中导航失败（网络断开）显示半透明"重新连接中..."横幅在窗口顶部，不阻塞地图查看，继续以当前已渲染内容展示。

### 窗口位置越界找回算法

启动时和显示器配置变化（`WM_DISPLAYCHANGE`）时执行：

1. 从设置中读取保存的窗口位置（Left, Top, Width, Height）
2. 枚举当前所有显示器的 WorkingArea
3. 如果窗口矩形与任一 WorkingArea 的交集面积 >= 窗口面积的 20%：保持原位
4. 否则：重置到主显示器右上角，偏移距右边缘 16px、距上边缘 16px，默认大小 640x360
5. 如果保存的 Width < 200 或 Height < 150 或 Width/Height 超过屏幕尺寸：重置为默认值 640x360

### WebView2 Runtime 检测

启动时调用 `CoreWebView2Environment.GetAvailableBrowserVersionString()`。如果返回 null 或抛出异常（Runtime 未安装），显示消息框：

> "Microsoft Edge WebView2 Runtime 未安装。请从 https://go.microsoft.com/fwlink/p/?LinkId=2124703 下载 Evergreen Bootstrapper 后重试。"

点击确定后退出（exit code 1）。不尝试自动安装。

### 窗口置顶维持机制

锁定模式下，每 2 秒通过 `SetWindowPos` 重新应用 `HWND_TOPMOST` + `SWP_NOACTIVATE`，使用 `System.Timers.Timer`。编辑模式下停止定时器（编辑模式不需要强制置顶维持）。如果实测发现此方案在 DirectX 12 全屏优化下不可靠，后备方案为 `AttachThreadInput` + 游戏窗口线程。
