## What Is NOT Unit Tested (by design)

| Component | Reason |
|-----------|--------|
| MainWindow.xaml.cs | WPF code-behind; binding glue only, no decision logic |
| EditOverlay.xaml.cs | WPF code-behind; binding glue only |
| Win32Interop.cs (WPF impl) | Thin P/Invoke wrapper with zero logic; 1:1 Windows API mapping |
| WebView2Setup.cs | WPF + WebView2; logic is navigation callbacks registered on CoreWebView2 |
| App.xaml.cs | WPF lifecycle; Mutex/single-instance glue |

**Rule:** All decision logic lives in Core. WPF is thin binding and P/Invoke. If a bug can exist in WPF code, the fix is to move the logic to Core and add a test.

## CI Pipeline

```yaml
# .github/workflows/test.yml
name: Test
on: [push, pull_request]
jobs:
  test:
    runs-on: windows-2022  # pinned for reproducibility
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-dotnet@v4
        with:
          dotnet-version: '8.0.x'
      - run: dotnet test tests/Anhei4Map.Core.Tests/
```

Gate: PR cannot merge if `dotnet test` fails.

## Test Run Commands

```bash
# Run all tests
dotnet test tests/Anhei4Map.Core.Tests/

# Run specific test class
dotnet test tests/Anhei4Map.Core.Tests/ --filter "FullyQualifiedName~WindowStateMachineTests"

# Run with verbose output
dotnet test tests/Anhei4Map.Core.Tests/ --logger "console;verbosity=detailed"
```
